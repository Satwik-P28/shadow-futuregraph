# Known limitations

Shadow does not predict every possible future. The graph is capped at about 80 nodes and 160 edges and keeps branches that reach a constraint, failure, or outcome.

Failure radius is the nearest discovered modeled failure under the declared ranges and the search budget. It is not a probability and not a guarantee that nothing closer exists outside the model.

Probabilities are omitted unless a distribution is actually declared and a rate can be computed without inventing one. Uniform ranges in the fixtures support a distance, not a claimed success rate.

Nemotron can propose a dependency or a repair that is wrong. The dinner-moving repair in the travel fixture is rejected because it violates a hard constraint. That rejection is the product, not a fallback slogan.

OpenShell prover coverage is limited to the domains the prover reports. This environment has no `openshell-prover` binary, so the status is `prover_unavailable`. Structural containment is a local check, not a formal proof.

External APIs fail. The hero path does not need them. Duffel, Google Calendar, and Tavily are implemented and stay dark until credentials exist. Real calendar writes also require `SHADOW_REAL_ACTIONS_ENABLED=true`. No real ticket is purchased.

The local ShadowBench generator is monotone and low-dimensional. Full Shadow scores perfectly on it because the robust repair is the unique plan with no discovered failure inside the box. That is a test of the search, not a claim about arbitrary personal plans. The scripted baselines are not Nemotron. No live 100-world Token Factory run was spent, because the architectural gap shows up without it and Ultra/Super stay off.

Z3 is used only when every variable is numeric and every hard constraint is a linear comparison. The travel scenario is reported as `unsupported` for that reason.

The second scenario, the apartment move, uses the same evaluator. There is no apartment-specific branch in the search.
